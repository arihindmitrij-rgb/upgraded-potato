# Агент-Логист WB

Автономный Python-скрипт для n8n: читает распределение из Google-таблицы,
подтягивает баркоды из Content API WB, генерирует ТЗ для фулфилмента (Excel)
и создаёт **черновик** поставки FBW. Слот/таймслот и дату приёмки скрипт
не бронирует — это делается вручную в кабинете WB.

```
wb-logist/
  wb_logist.py          # CLI (stdout — только JSON for n8n)
  wb_logist/
    config.py           # .env + переменные окружения + CLI-оверрайды
    sheets.py           # чтение Google Sheets строго по gid + разбор CSV
    errors.py           # WbLogistError(code, message)
    models.py           # Distribution / DistributionRow / SkippedRow
  tests/                # unittest, без сети
  output/               # сюда пишутся xlsx и манифест
```

## Требования

- Python 3.11+ (проверено на 3.14.2)
- пакеты: `requests`, `openpyxl`

### Ozon

```powershell
.\.venv\Scripts\python.exe wb_logist.py --marketplace ozon --dry-run --verbose
```

- Лист: свежий `Баранов ОЗОН …`; Excel → `Desktop\ТЗ Ozon` (сумма qty).
- Черновик multi-cluster с разбивкой по городам — только без `--dry-run` и с
  `OZON_DROP_OFF_WAREHOUSE_ID` (точка из `/v1/warehouse/fbo/list`).
- WB-путь (`--marketplace wb` / «делай распред») не затрагивается.

## Контракт для n8n

- `stdout` — ровно одна JSON-строка, `stderr` — логи.
- Успех: `exit code 0`, `{"status": "success", ...}`.
- Ошибка: `exit code 1`, `{"status": "error", "error": "...", "error_code": "..."}`.

## Лист распределения

По умолчанию (`--marketplace wb`) берётся **самый свежий** лист
`Баранов ВБ DD.MM[.YYYY]` (образец: `Баранов ВБ 05.11.2026`).
Явный `--gid` / `--sheet` или `--legacy-sheet` (SHEET_GID/SHEET_NAME из `.env`)
перекрывают авто-выбор.

Форматы листа:

- классика: `Артикул продавца` + `Количество`;
- новый: `Артикул продавца` + колонки складов/городов — чистые числа
  **суммируются** в одно количество (ТЗ/черновик WB как раньше).

Правила ячеек:

- чистое число (`50`, `1 000`) — берём;
- рядом с числом текст/дробь (`30 /10`, `10 шт`, `нет же?`) — **не** берём;
- пусто / ноль — пропуск (`skipped`);
- дубли артикулов суммируются.

Почему не `gviz/tq?sheet=...`: Google молча отдаёт первый лист. Имя → gid
через `htmlview`.

## Генерация ТЗ (этап 2)

- Шаблон: `templates/tz_template.xlsx` — копия вашего `ИП_Баранов_ВБ.xlsx`
  (лист «ТЗ Экспо Карго» + «ТЗ по упаковке»).
- Заполняются товарные строки: `A` №, `B` название из карточки, `E` размер
  (значение `0` от WB считаем отсутствующим), `F` артикул, `G` телефон,
  `J` баркод **текстом**, `K` количество, `L` ИП, `M` бренд, `P` формула `=K*2`.
- Строка «На какой склад требуется отгрузка» получает `R = ВБ`
  (`DESTINATION_MARKER`).
- Чек-лист услуг и оформление шаблона не переписываются: лишние товарные
  строки очищаются (услуги в колонке `N` остаются), при нехватке строк
  добавляются новые со стилем последней товарной строки.
- Файл кладётся в `REPORT_DIR` (по умолчанию `C:\Users\User\Desktop\ТЗ WB`)
  с именем `REPORT_PREFIX + дата`, например `ИП Баранов ВБ 19.11.2026.xlsx`.
  Если файл открыт в Excel — рядом пишется копия с меткой времени.
- Манифесты прогонов (`output/manifest_*.json`) остаются в папке проекта.

Известное ограничение: `openpyxl` не сохраняет картинки из шаблона, поэтому
фото-примеры на листе «ТЗ по упаковке» в сгенерированном файле отсутствуют
(текст инструкций сохраняется).

## Черновик поставки (этап 3)

- `POST /api/supplies/v1/drafts` → `{"draftId": "..."}` (пустое тело, имени и склада нет).
- `POST /api/supplies/v1/drafts/{id}/items` → `{"items": [{"sku": "<баркод>", "quantity": N}]}`,
  чанками по 1000, ответ `{"results": []}` = всё принято.
- Любая ошибка → `DELETE /api/supplies/v1/drafts/{id}` (откат) и `status: error`.
- Слот, таймслот и дата приёмки не бронируются.
- **Защита от дублей:** если за последние 24 часа уже есть черновик с точно таким же
  набором `sku → quantity`, новый не создаётся — бот присылает файл и id существующего.
  Принудительно: `--allow-duplicate` (в боте — «делай распред дубль»).
- `--dry-run` — полный прогон без создания черновика (ТЗ + манифест).

Требование к токену: категория **Поставки** с правом **записи**. С read-only
токеном WB отвечает `403 read-only token cannot perform non-readonly requests`.

## Telegram-бот (этап 4)

Бот `@fbsxoradobot` слушает команды сам (long polling), n8n не участвует.

| Команда | Что делает |
|---|---|
| «делай распред» / «погнали» | свежий лист «Баранов ВБ …», баркоды, ТЗ, черновик FBW |
| «делай озон» | свежий «Баранов ОЗОН …» → ТЗ (черновик Ozon — если ключи ок) |
| «статус» | проверяет, что бот на связи |
| «помощь» | подсказка |

- Ответ приходит **в личку** тому, кто написал.
- Файл кладётся в `REPORT_DIR`, отправляется документом с подписью (draft_id, штук).
- Логи: `logs\bot.log` (ротация 2 МБ × 3).
- Защита: один воркер на машину (порт-замок 45911), старые сообщения (до старта воркера) не выполняются.

### Запуск

```powershell
.\.venv\Scripts\python.exe bot_worker.py            # в консоли
.\.venv\Scripts\python.exe bot_worker.py --check    # проверить токен
start_bot.vbs                                       # без окна
```

### Автозапуск

Задача Планировщика **«WB Logist Bot»** (триггер «при входе в систему», перезапуск при сбое).
Проверить: `schtasks /query /tn "WB Logist Bot"`. Удалить: `schtasks /delete /tn "WB Logist Bot" /f`.

Важно: ПК должен быть включён и не в спящем режиме — иначе бот не ответит.
